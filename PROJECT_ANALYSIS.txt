3.  TELEGRAM / aiogram  (dispatcher.py, middleware.py)
================================================================================

[HIGH] dispatcher.py:12  `print(TOKEN)` — bot token printed to stdout on
    every startup.  Anyone with log access can steal the bot.

[MED]  dispatcher.py uses one global `bot` and `dp`.  The Bot session is
    never explicitly closed on shutdown -> sockets leak between reloads.

[MED]  mafia_bot/middleware.py:7-10  `DjangoDBMiddleware` closes ALL Django
    DB connections after every Telegram update:
        for conn in connections.all():
            conn.close()
    This defeats Django's CONN_MAX_AGE / connection pooling and adds round-
    trip cost on every callback.  Should call `close_old_connections()` only.

[HIGH] Throughout handlers: Django ORM is called synchronously from async
    aiogram handlers without sync_to_async wrappers (e.g. callback_handlers.py
    lines 39, 48, 53, 221, 392, 396, 851, 1625, 1643, …, command_handlers.py
    lines 36, 112, 211, 220, 292, 306, 400, 545, 559, 591, 613, 669, 1173,
    1226, 1262-1272, …).  Django 5 will RuntimeError ("SynchronousOnlyOperation")
    when async-unsafe is detected, and in any case blocks the event loop.
    Only a few hot paths use sync_to_async (`take_stone`, `take_gsend_stone`,
    `claim_channel_olmos`) — the rest is broken/slow.

10. CROSS-CUTTING / ARCHITECTURE
================================================================================

[CRIT] EVERY in-memory dict in mafia_bot/utils.py
    (games_state, last_wishes, team_chat_sessions, game_tasks, notify_users,
     group_users, stones_taken, gsend_taken, giveaways, active_role_used,
     writing_allowed_groups, USER_LANG_CACHE, game_locks, chat_id_game_id)
    is mutable module state, single-process.  If the bot is restarted, all
    in-flight games / pending rewards / channel olmos drops are LOST.  No
    persistence layer.  Use Redis or restart-safe storage.

[HIGH] Concurrency:
    - threading.Lock used inside async (main_functions.py line 20, 312, 745
      848, 922, 1013) blocks the event loop.
    - game_locks dict is built lazily without its own lock (race in
      get_game_lock) — two simultaneous /game commands can both miss the
      key and create two locks.
    - All Telegram payment / coin / stones updates use raw read-modify-
      write.  Should use F() expressions inside .update() OR transaction
      with select_for_update.

[HIGH] Trusting callback_data as user input.  Many handlers use values from
    callback.data (target_id, game_id, day, chat_id) without verifying the
    presser is allowed.  Examples: traitor / spy callbacks (anyone with the
    raw callback data can hijack the role action), com shoot / check, hero
    attack on arbitrary target.  Spoof-able by anyone who copies a callback
    string.

[HIGH] Money-flow auditing:
    - MoneySendHistory.amount is a free-form string with emoji prefix; cannot
      compute totals or detect double-spends.
    - case_buy_callback / open_case_callback grants stones based on integer
      embedded in callback_data — must be replaced with a server-side draw.

[MED]  i18n consistency:
    - LANG_TEXTS imports uz_texts / ru_texts / en_texts / tr_texts / qz_texts
      via wildcards from core/constants — partial-translation typos (e.g.
      uz "com" emoji-id is "5886694236165773623" 🕵🏻‍♂️ vs DESCRIPTIONS uses
      "5886694236165773623" 🕵🏻 — slight mismatch). Hard to keep aligned.
    - DESCRIPTIONS["lucky"] is referenced but role "lucky" is not in
      ROLES_BY_COUNT — dead description.
    - DESCRIPTIONS adv / lab / kaldun / daydi all contain BROKEN UTF-8
      replacement characters (` <tg-emoji emoji-id='…'>�</tg-emoji>`) —
      indicates copy-paste through a non-utf8 editor.
    - ROLE_EMOJIS["arrow"] ends with a stray "️" variant selector — fine,
      but consistency.

[MED]  ROLES_BY_COUNT (core/constants.py:1677-1714) never assigns the role
    "hero" — yet ROLE_EMOJIS and DESCRIPTIONS have it, and game logic
    branches on hero (callback_handlers.py:3823 hero_callback).  Hero is

[MED]  game_handler.py:48  `users_map = games_state[game_id].get("users_map",
